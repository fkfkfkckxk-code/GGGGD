# Связь — мессенджер для друзей (Android)

Приложение для переписки и голосовых звонков с друзьями. Написано на Kotlin,
данные хранит в Firebase (сервис Google), звонки работают по технологии WebRTC.

## Что умеет приложение

- **Вход** — через аккаунт Google или по номеру телефона с кодом из SMS.
- **Профиль** — имя, фото и уникальный ник (например, `@ivan_petrov`).
- **Друзья** — поиск человека по нику, номеру телефона или почте Google.
  Заявка отправлена → друг принял → вы в списке друзей друг у друга.
- **Чаты один на один** — текст, эмодзи, фото и голосовые сообщения.
  Сообщения приходят сразу, у каждого виден статус: отправлено ✓, доставлено ✓✓,
  прочитано ✓✓ (синие галочки).
- **Голосовые звонки** — один на один, с выключением микрофона и громкой связью.

## Что важно знать заранее

1. **Код из SMS на настоящий номер — платная функция Firebase.** Google отправляет SMS
   только проектам с подключённой оплатой (тариф Blaze), а российские карты не принимает.
   Без оплаты вход по телефону работает с *тестовыми номерами* (шаг 5) — этого достаточно,
   чтобы всё проверить. Вход через Google бесплатный и работает сразу.
2. **Уведомлений пока нет.** Сообщения и входящие звонки приходят, пока приложение
   открыто. Чтобы телефон «звонил» при закрытом приложении, нужен свой сервер или
   платные функции Firebase — это следующий этап (см. конец файла).
3. **Работа в России.** Firebase — сервис Google. Официально он не заблокирован и обычно
   открывается без VPN, но доступ к сервисам Google в России бывает нестабильным,
   а при «белых списках» мобильного интернета не работает совсем. Гарантировать
   работу без VPN всегда и везде нельзя — это не зависит от кода приложения.
4. **Звонки соединяют телефоны напрямую.** В домашнем Wi-Fi это обычно получается,
   а в части мобильных сетей — нет. Для надёжных звонков нужен TURN-сервер
   (подсказка — в файле `app/src/main/java/com/svyaz/app/call/CallConfig.kt`).
5. **Фото и голосовые хранятся в самой базе данных**, потому что файловое хранилище
   Firebase доступно только на платном тарифе. Поэтому фото сжимаются,
   а голосовое сообщение — не длиннее 3 минут.

Бесплатного тарифа Firebase (Spark) хватает с запасом для компании друзей:
1 ГБ данных, 50 000 чтений и 20 000 записей в сутки. Карта для него не нужна.

## Как запустить: шаг за шагом

### Шаг 1. Установите Android Studio

Android Studio — программа, в которой пишут и запускают приложения для Android.
Скачайте её с <https://developer.android.com/studio> и установите, ничего не меняя
в настройках установщика.

### Шаг 2. Откройте проект

1. Скачайте проект с GitHub: зелёная кнопка **Code → Download ZIP**, затем распакуйте архив.
2. В Android Studio выберите **File → Open** и укажите распакованную папку
   (ту, в которой лежит файл `settings.gradle.kts`).
3. Подождите. При первом открытии Android Studio сама скачивает всё нужное — это может
   занять 5–15 минут. Пока файла из шага 3 нет, сборка будет ругаться
   `File google-services.json is missing` — это нормально.

### Шаг 3. Создайте проект Firebase и подключите приложение

Firebase — это готовый сервер от Google: он хранит пользователей и сообщения.

1. Откройте <https://console.firebase.google.com> и войдите со своим аккаунтом Google.
2. Нажмите кнопку создания проекта, придумайте название. Google Analytics можно выключить.
3. На главной странице проекта нажмите на **значок Android** (или **Add app**).
4. В поле **Android package name** впишите точно: `com.svyaz.app`
5. Нажмите **Register app**, затем **Download google-services.json**.
6. Положите скачанный файл в папку **`app`** внутри проекта — рядом с файлом
   `app/build.gradle.kts`. (В Android Studio слева вверху переключите вид с *Android*
   на *Project*, чтобы увидеть настоящие папки.)
7. Остальные шаги мастера («Add Firebase SDK») пропускайте кнопкой **Next** — в проекте
   это уже сделано.

Файл `google-services.json` у каждого свой, поэтому в репозитории его нет.

### Шаг 4. Добавьте «отпечатки» приложения (SHA)

Так Google убеждается, что вход запрашивает именно ваше приложение.

1. В Android Studio откройте вкладку **Terminal** (внизу окна) и выполните команду:
   - Windows: `.\gradlew signingReport`
   - macOS и Linux: `./gradlew signingReport`
2. В ответе найдите блок `Variant: debug` и в нём строки **SHA1** и **SHA-256**.
3. В консоли Firebase: **шестерёнка → Project settings → General → Your apps** → ваше
   приложение → **Add fingerprint**. Вставьте значение SHA1 и сохраните.
   Потом так же добавьте SHA-256.

### Шаг 5. Включите способы входа

В консоли Firebase откройте **Security → Authentication** (в старом виде консоли —
**Build → Authentication**), нажмите **Get started** и перейдите на вкладку **Sign-in method**.

**Google**
1. Выберите **Google**, включите переключатель **Enable**.
2. Укажите свою почту в поле поддержки и нажмите **Save**.
3. **Обязательно** скачайте `google-services.json` заново (**шестерёнка → Project settings →
   Your apps → google-services.json**) и замените им старый файл в папке `app`.
   Без этого кнопка «Войти через Google» покажет ошибку.

**Телефон**
1. Выберите **Phone**, включите **Enable**, нажмите **Save**.
2. Добавьте тестовый номер: раскройте раздел **Phone numbers for testing**, впишите
   выдуманный номер, например `+1 650-555-1234`, и код, например `123456`. Нажмите **Add**.
3. Теперь в приложении можно войти с этим номером и этим кодом. SMS при этом не
   отправляется, оплата не нужна. Тестовых номеров может быть до 10 — по одному на друга.

Чтобы коды приходили на настоящие номера, нужно подключить к проекту оплату
(тариф Blaze) и разрешить отправку в Россию: **Authentication → Settings →
SMS region policy → Allow → Russia**.

### Шаг 6. Создайте базу данных и опубликуйте правила

1. В консоли Firebase откройте **Databases & Storage → Firestore** (в старом виде —
   **Build → Firestore Database**) и нажмите **Create database**.
2. Выберите расположение в Европе (название начинается с `eur` или `europe`) —
   оно ближе всего к России. Изменить его потом нельзя.
3. Выберите **Production mode** и нажмите **Create**.
4. Перейдите на вкладку **Rules** (Правила). Удалите весь текст и вставьте вместо него
   содержимое файла **`firestore.rules`** из корня проекта. Нажмите **Publish**.

Правила — это защита данных: сервер по ним решает, кому что можно читать и писать.
Без них приложение будет отвечать «Сервер отклонил действие».

### Шаг 7. Запустите приложение

- **На телефоне (лучше всего).** Включите на телефоне «Режим разработчика» и
  «Отладку по USB», подключите его кабелем и разрешите отладку.
- **На эмуляторе.** В Android Studio: **Device Manager → Create Virtual Device**,
  выберите телефон и систему **с Google Play**.

Выберите устройство вверху окна и нажмите зелёную кнопку **▶ Run**.

### Шаг 8. Проверьте вдвоём

Нужны два аккаунта: два телефона или телефон и эмулятор.

1. Войдите на обоих устройствах и создайте профили с разными никами.
2. На первом: **Друзья → Добавить друга**, найдите второго по нику, нажмите
   **Добавить в друзья**.
3. На втором: вкладка **Друзья** → примите заявку (галочка).
4. Нажмите на друга — откроется чат. Отправьте текст, фото, голосовое.
5. Нажмите на трубку вверху чата — у друга появится входящий звонок.
   Приложение у него должно быть открыто.

## Как передать приложение друзьям

В Android Studio: **Build → Generate App Bundles or APKs → Generate APKs**. Готовый файл
появится в `app/build/outputs/apk/debug/app-debug.apk`. Отправьте его друзьям — при
установке телефон попросит разрешить установку из этого источника.

Собирайте файл на том же компьютере, с которого брали отпечатки в шаге 4, иначе вход
через Google у друзей не заработает.

## Как устроен проект

Весь код — в папке `app/src/main/java/com/svyaz/app/`. В каждом файле есть комментарии.

| Папка или файл | Что внутри |
| --- | --- |
| `MainActivity.kt`, `SvyazApp.kt`, `AppContainer.kt` | Запуск приложения и общие объекты |
| `data/` | Работа с сервером: вход, профили, друзья, сообщения, звонки |
| `data/Models.kt` | Какие данные есть в приложении (профиль, сообщение, чат…) |
| `ui/auth/` | Экран входа |
| `ui/profile/` | Создание и редактирование профиля |
| `ui/home/` | Главный экран: вкладки «Чаты», «Друзья», «Профиль» |
| `ui/friends/` | Поиск и добавление друга |
| `ui/chat/` | Экран переписки: сообщения, поле ввода, эмодзи, фото, голосовые |
| `ui/call/` | Экран звонка |
| `call/` | Сам звонок: соединение WebRTC, звук, служба звонка |
| `media/` | Сжатие фото, запись и воспроизведение голосовых |
| `ui/theme/Theme.kt` | Цвета приложения |
| `firestore.rules` (в корне) | Правила доступа к базе данных |
| `gradle/libs.versions.toml` | Список библиотек и их версий |

Название приложения меняется в `app/src/main/res/values/strings.xml`.

## Если что-то не работает

| Что видите | Что сделать |
| --- | --- |
| `File google-services.json is missing` | Положите файл в папку `app` (шаг 3) |
| «Вход через Google не настроен» | Включите Google в консоли и скачайте `google-services.json` заново (шаг 5); добавьте SHA1 (шаг 4) |
| «SMS не отправляются: … не подключена оплата» | Войдите по тестовому номеру (шаг 5) |
| «Сервер отклонил действие» | Опубликуйте правила из `firestore.rules` (шаг 6) |
| «База данных не найдена» | Создайте базу Firestore (шаг 6) |
| Бесконечная загрузка после входа | Проверьте интернет; убедитесь, что база создана (шаг 6) |
| Звонок не соединяется («Не удалось установить соединение») | Попробуйте, когда оба телефона в Wi-Fi. Для мобильных сетей нужен TURN-сервер — см. `call/CallConfig.kt` |
| Android Studio не может скачать Gradle | В файле `gradle/wrapper/gradle-wrapper.properties` замените адрес в строке `distributionUrl` на зеркало: `https\://mirrors.cloud.tencent.com/gradle/gradle-9.6.1-bin.zip` |

## Что можно добавить дальше

- **Уведомления** о сообщениях и звонках при закрытом приложении (Firebase Cloud
  Messaging + небольшой сервер).
- **Коды SMS через российского оператора рассылок** — чтобы вход по телефону работал
  без зарубежной карты (тоже нужен небольшой сервер).
- **Свой TURN-сервер** — чтобы звонки соединялись в любых сетях.
- Видеозвонки, групповые чаты, удаление и пересылка сообщений.

Если решите открыть приложение не только для друзей, а для всех — заранее изучите
требования закона о персональных данных (152-ФЗ): данные пользователей в этом варианте
хранятся на серверах Google за рубежом.
